## 5. Authentication Flow

- Provider: `CredentialsProvider` (email + password)
- Strategy: JWT (no database sessions)
- Password hashing: bcrypt cost factor 12
- Sign-in / error page: `/admin/login`
- Client guard: `useSession()` in `AdminLayout` — redirects unauthenticated users to `/`
- Server guard: `getServerSession(authOptions)` used in API routes and sensitive server actions
- Token propagation: `jwt` callback stores `user.id`; `session` callback exposes it as `session.user.id`

## 11. Event Lifecycle (State Machine)

```
DRAFT ──► ACTIVE ──► FILLED  (auto: interests >= slotsNeeded, via Prisma transaction)
             │
             ▼
           CLOSED  (manual: admin sets status in edit form)
```

- Auto-fill runs inside `prisma.$transaction` in `createInterest()`
- Duplicated events always start as DRAFT
- Public EventBrowser only shows ACTIVE and FILLED events
- Public event detail page shows 404 for DRAFT and CLOSED

## 13. Web Push Notification Flow

1. `AdminLayout` mounts `PushNotificationManager` on every admin page
2. On mount: registers `/sw.js` as service worker
3. Requests `Notification.requestPermission()` from browser
4. Fetches existing subscription; if none exists: subscribes with VAPID public key
5. POSTs subscription `{ endpoint, keys: { p256dh, auth } }` to `/api/push/subscribe`
6. On each new `createInterest()` server action:
   - Fetches all `PushSubscription` records from DB
   - Calls `webpush.sendNotification()` for each subscription
   - Dead subscriptions (HTTP 404 or 410 from push service) are auto-deleted
7. Service Worker (`public/sw.js`):
   - `push` event: calls `self.registration.showNotification(title, options)`
   - `notificationclick` event: opens `/admin/leads` in the browser

## 14. Image Upload Flow (Cloudinary)

1. Admin opens event create/edit form
2. `CloudinaryUpload` component renders upload widget
3. Widget calls `/api/cloudinary-sign` POST with `{ paramsToSign }`
4. Server computes `cloudinary.utils.api_sign_request(params, API_SECRET)` and returns signature + apiKey
5. Widget posts directly to Cloudinary REST API (no file passes through Next.js server)
6. Cloudinary returns `secure_url` → stored in `Event.imageUrl` or `Interest.paymentScreenshot`
7. `next.config.mjs` allows `https://**` and `res.cloudinary.com` for Next.js `<Image>` component

Note: `/api/cloudinary-sign` has no session guard currently — any client can call it.

## 17. Naming & Code Conventions

- **Server Actions** — always `'use server'`; all DB calls via `withRetry()`; `revalidatePath()` after every mutation
- **Client Components** — `'use client'`; data loaded in `useEffect`; local state via `useState`; no SWR/React Query
- **Form pattern** — controlled components; Zod validates on server; client shows inline error messages per field
- **Tailwind** — utility-first; `cn()` for conditional class merging; shadcn design tokens used throughout (`bg-card`, `text-muted-foreground`, `bg-primary/10`, etc.)
- **Icons** — Lucide React exclusively; `h-4 w-4` for inline/nav icons, `h-5 w-5` for card titles, `h-8 w-8` for quick action cards
- **Heading hierarchy** — `h1` per page, `h3` for section cards, `h4` for list item titles (avoids H1→H4 skip)
- **Phone masking** — phones are masked by default in leads table; toggled per-row by admin

## 18. Known Limitations & Technical Debt

| Item | Detail |
|------|--------|
| In-memory rate limiter | Resets on cold start; needs Redis for production scale |
| Platform Settings toggles | Not persisted to DB — state is UI-only |
| Roles & Permissions table | Display-only, no actual enforcement |
| `any` types | Used in event/lead list components; Prisma types not propagated to client |
| `window.confirm()` for delete | Not accessible; should be replaced with a shadcn Dialog |
| CSV export path | Leads page calls server action -> blob download; cleaner to use `/api/interests?export=true` |
| `/api/cloudinary-sign` | No auth guard — any caller can request a valid Cloudinary signature |
| No pagination | Events and leads lists load all records at once; will degrade at scale |
| Settings tab notifications | Toggle onChange is `() => {}` (no-op) — UI-only, not wired |
